# Shared workspace governance baseline

Owner: the workspace policy owner. Consumer adoption binds the immutable
`workspace/policy-kit` distribution; stronger project authorities retain scope.

## Before changing a consumer

Resolve the consumer identity, inherited instructions, selected routes and
owning design sources. State a bounded plan and acceptance criteria. Protect
unrelated changes, external inputs, generated provenance and compatibility.
Execution mode controls discovery cost; evidence follows task, diff, claims and
risk. Resolved facts with provenance suffice until semantics, ambiguity,
conflict, boundary review or an authority edit requires canonical source text.

## Evidence and updates

Keep required checks in the actual verification runner. Add behavioural evidence
when behaviour changes; retain semantic review duties where automatic checks
are partial. Update affected design/docs/backlog according to consumer authority
and applicable session instructions. Machine thresholds are declared bindings,
not generic proof of quality. Never report unavailable evidence as passing.

## Safety and ownership

Never introduce or print secrets. Keep protected data read-only and derived
outputs at declared consumer locations. Avoid destructive Git/data operations
without explicit authorization. Machine interpreter selections stay in permitted
local configuration; project execution and governance runtime are distinct.
Do not weaken inherited sanitation or stricter consumer checks during adoption.

## Pack maintenance

A skill guides the workflow; it does not own policy or enforce gates. Authority
changes require a scoped record, equivalent obligations and required independent
review. Immutable release identity and consumer lock establish byte provenance;
a mutable remote, version label or local re-blessed hash does not establish
canonical adoption. Preserve deferred comparison/blocking and telemetry evidence
gates. Any scan, adoption or product-verification gap stays explicit.

## Execution completion

All consumer work follows [Completion-based execution without autonomous polling](execution.md). The pack manifest binds its machine contract; `execution.completion` supplies the resolved policy and provenance. Local verification waits for exit. Remote state is observed once, only when the declared gate requires it; pending is reported as `PENDING_EXTERNAL` and ends the observation. Watch and interval modes, sleep loops and repeated status requests are prohibited and are blocked before execution by the pack-managed PreToolUse guard.
